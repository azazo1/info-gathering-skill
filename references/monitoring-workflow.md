# 持续监测工作流

一次性调研走 SKILL.md 的七阶段. 要长期跟踪一个领域 (每日 / 每周追新模型, 新版本, 新政策) 时用本流程. 流程参考橘鸦 AI 早报公开的做法 (bilibili BV1JmdhYqEoy "深度揭秘! AI日报工作流和信息源", BV1B82DBdEdP "我的 AI 早报生产线大公开"), 开源实现基于 yihong0618/gitblog.

## 一, 流程

```
订阅池 -> 定时抓取 -> 存成 markdown -> 相关性过滤 -> 价值过滤 -> 历史去重 -> 分类 -> 人工筛选 -> 整理成稿 -> 核对来源 -> 发布
```

1. 订阅池: 以 RSS 为主. 领域信源从 `ai-tech-sources.md` 等信源文件挑, 不超过 20 个
2. 定时抓取: 抓到的每一条存成一个 markdown 文件, 保留原始链接与时间
3. 相关性过滤: 去掉和主题无关的条目
4. 价值过滤: 去掉个人体验, 教程分享, 营销内容这类没有报道价值的条目
5. 历史去重: 每条先生成一段概要, 用概要和历史稿件比对, 去掉已经报道过的事件. 同一事件会在多个渠道连续出现好几天, 这一步不能省
6. 分类: 按固定栏目分类, 方便人工筛选. 栏目可沿用橘鸦的: 要闻, 模型发布, 开发生态, 产品应用, 技术与洞察, 行业动态, 前瞻与传闻
7. 人工筛选: 自动过滤之后仍需要人看一遍. agent 执行时, 把候选清单交给 user 确认, 不要自己决定最终收录
8. 整理成稿: 把选中的条目一次性交给长上下文模型整理, 每条写标题, 摘要, 正文, 相关链接
9. 核对来源: 保留合适的原始链接与图片, 去掉二手转载链接
10. 发布: 输出 markdown, 再按需生成 RSS, 网页, 音视频

## 二, 经验

- 不要订阅太多信源. 同一事件会在多个渠道反复出现, 信源越多, 去重成本越高
- 爬虫是个深坑. 先用 RSS 和官方 API, 爬不到的少数站点再用 browser, 不要一开始就写通用爬虫
- 不要先搜索再爬原文去补全每个事件. 橘鸦试过 "用关键词搜 24 小时内相关信息, 再爬原文与媒体资源" 的方案, 最后放弃, 改为直接把筛选后的条目交给模型整理
- 栏目里的 "前瞻与传闻" 单独放, 不要和事实混在一起
- 每条保留 "相关链接" 列表, 方便读者回到一手来源
- 综合日报会漏垂直领域的事件. 跟踪垂直领域时, 订阅池里必须有该领域的社区与 changelog (见 `ai-tech-sources.md` 第六节)

## 三, 在本 skill 里落地

目录:

```
.research/<slug>/
- sources.txt        # 订阅池, 一行一个 RSS 或页面地址
- inbox/             # 每次抓取的原始条目, 按日期分子目录
- history.md         # 已收录事件的概要, 用于去重, 只追加
- digests/           # 每期产出, 例如 2026-11-06.md
```

每期执行:

1. 读 `sources.txt`, 抓取新条目到 `inbox/<日期>/`
2. 过滤与分类后, 和 `history.md` 比对去重
3. 输出候选清单, 交 user 确认 (ask)
4. 按确认结果写 `digests/<日期>.md`, 每条带原始链接
5. 把本期收录事件的概要追加到 `history.md`

需要定时执行时, 由 user 明确要求后再创建定时任务, 不要自己创建.
