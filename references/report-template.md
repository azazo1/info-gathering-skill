# 报告模板

报告写进 `.research/<slug>/report.md`, 中文正文, 引用来源编号. 骨架如下, 按需增删分节, 但摘要与参考来源两节必须保留.

```markdown
# <标题>

调研日期: 2026-11-06
范围: <时间窗, 地域, 语言, 版本>
来源数量: <N 个, 一手 <a> / 权威 <b> / 普通 <c> / 待验证 <d>>

## 摘要

三到五条要点, 每条一到两句, 挂引用.

## 结论

直接回答 brief 里的核心问题. 如果证据不足, 写明不足在哪, 不要硬下结论.

## <子问题 1>

- 事实陈述挂引用 [S1].
- 需要对比时用表格.
- 有分歧时在段末写冲突说明.

## <子问题 2>

...

## 冲突与不确定性

| 断言 | 来源 A 的说法 | 来源 B 的说法 | 处理方式 |
|---|---|---|---|
| ... | ... | ... | 取 A, 因为 ... |

没有冲突就写 "未发现来源间冲突".

## 未覆盖的部分

- 哪些来源抓取失败, 缺失可能影响哪个结论
- 哪些子问题没有找到足够证据

## 开放问题

还需要跟踪或验证的点, 写成可执行的问题.

## 参考来源

- [S1] 标题, 发布者, 发布时间, URL (可信度: 一手)
- [S2] ...
```

## 写法要求

- 每条事实后挂来源编号, 编号只用 sources 中存在的
- 数字, 日期, 名称要以来源为准, 多个来源不一致时列出差异
- 观点与推断单独标注, 例如 "推断: ...", 并给出依据
- 措辞直接, 不写 "综上所述" 之类的空话
- 中英文混排时保留盘古之白, 即数字, 英文与汉字之间加空格
- 报告是给人读的, 不要把检索过程流水账搬进来, 过程留给 plan.md

## 时效声明

报告开头写调研日期. 对时效敏感的结论 (价格, 版本, 政策) 额外写一句: "以下信息以 2026-11-06 抓取为准, 之后可能已变化".
